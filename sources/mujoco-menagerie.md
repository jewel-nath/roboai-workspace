# MuJoCo Menagerie: what it gives RoboAI

Google DeepMind's curated collection of MJCF models for MuJoCo: 73 gallery entries in 71 model
folders, from humanoids, quadrupeds and arms to hands, two drones, a camera and three
biomechanical models. Each folder carries its own licence (32 Apache-2.0, 22 BSD-3-Clause, 13 MIT,
3 BSD-2-Clause, 1 BSD-3-Clause-Clear), a README with the steps that derived the model from the
maker's URDF or CAD, and a changelog; a `mujoco-menagerie` pip package downloads and pins them.
For Phase 5 it gives one page, the collection itself, for the CAD-to-sim batch. The models are not
pages: 52 of the 73 entries are robots the Atlas already profiles, and 48 of those are already
named in their page's `stack.sim_models`. The rest are index rows, a few of them worth an Atlas
card later.

## How it was read

- Read at commit `eea4c74` (2026-11-23) on 2026-11-26 from a blob-less partial clone with full
  history and a sparse checkout of the Markdown and `LICENSE` files only (no meshes; nothing run).
  Read in full: the README (353 lines, with the generated gallery of 73 entries in 11 sections),
  `FAQ.md`, `CHANGELOG.md` and `AGENTS.md`; in part: `CONTRIBUTING.md`, `python/DOC.md`, and the
  overview of each model README whose robot is not in the Atlas.
- Rows: one per gallery entry. "Panda Gripper" and "xarm7 Gripper" are second entry points
  (`hand.xml`) in the `franka_emika_panda` and `ufactory_xarm7` folders, so 73 rows come from 71
  folders. One more row is the collection itself. DoF figures are the gallery's.
- Licences: each folder's `LICENSE` was read and classified; all 71 agree with the gallery's
  labels. The repo's own tooling is Apache-2.0; its root `LICENSE` is generated by joining the
  per-model licences. `kuka_iiwa_14` carries Drake's BSD-3-Clause licence.
- Last commit: `git log -1 -- <folder>` on the clone. Two repo-wide clean-ups touched most
  folders: 2026-11-02 (lights moved to scene files, actuator force limits migrated) and
  2026-07-04 (scene camera tags). Those dates show the folder is kept in step with the repo, not
  that the model itself changed.
- Atlas check: each robot was matched to `wiki/robots/` by name, and the page's frontmatter
  `stack.sim_models` was searched for the folder name. Four Atlas-covered entries are not in
  `sim_models`: `toddlerbot_2xc` and `toddlerbot_2xm` (the ToddlerBot page names only the
  ToddlerBot repo's own models), `robotis_omy_3m` (named in the OpenManipulator-X body, not its
  stack) and `trossen_wxai` (named in the Interbotix table, not its stack). The Robot Soccer Kit
  page says "MuJoCo Menagerie" without the folder name. Berkeley Humanoid is the 2024 research
  robot of the Hybrid Robotics lab, not the Lite the Atlas profiles; Fourier N1 is not the GR-1.
- Not in the Atlas but possibly worth a card: Seeed reBot DevArm (its hardware repo is
  CERN-OHL-W, last commit 2026-11-25), I2RT YAM (sold; MIT SDK, last commit 2026-11-26) and
  Fourier N1 (Fourier calls it open source; its page did not render, so unconfirmed).
- `wiki/tools/mujoco.md` already has a Menagerie section, and two Phase 4 notes
  (awesome-robotics-libraries, awesome-robot-learning) point their Menagerie rows at it. This note
  uses the Phase 5 shared slug `software/mujoco-menagerie`; the new page takes the per-model
  detail, the pip package (added 2026-09-01; latest tag `v2026.11.3`, 2026-11-10), the
  live.mujoco.org browser viewer and the third-party `robot_descriptions` package the README
  names.
- Errors in the list: the `pndbotics_adam_lite` README links Sawyer's meshes in its derivation
  step; the `trossen_wxai` README links the ViperX 300 product page; the README's grading section
  still says the system identification toolbox is planned for "later this year" (text from
  2022), and its pip example pins `2026.9.0`.
- Addressed to agents: `AGENTS.md` (added 2026-11-23) gives rules to "contributors, reviewers,
  and coding agents" working in that repo, for example never to add AI assistants as commit
  co-authors. It concerns Menagerie's contributors only; nothing in it was acted on. The I2RT
  repo, cloned to check YAM's licence, ships its own `AGENTS.md` and `CLAUDE.md`; they were not
  read or followed.
