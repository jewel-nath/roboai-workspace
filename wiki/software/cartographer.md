# Cartographer

Google's real-time SLAM library for 2D and 3D lidar, with `cartographer_ros` for ROS; both are
Apache-2.0 [1][3]. **Unmaintained upstream:** no new development and no issue response; last
commits 2024-01-05 (`cartographer`) and 2022-10-27 (`cartographer_ros`) [1][2]. ROS 2 binaries
come from Open Robotics' forks `ros2/cartographer` and `ros2/cartographer_ros`, maintained "in a
limited capacity" (last commits May 2025) and released for Humble to Lyrical [1][3][4][8].

## When to use it

- **New 2D robot, above all with Nav2:** use [SLAM Toolbox](slam-toolbox.md); it is maintained.
- **Existing robot with tuned Lua configs:** keep it; TurtleBot3 has `turtlebot3_cartographer` [8].
- **3D lidar:** it needs an IMU there [6]; [RTAB-Map](rtab-map.md), [KISS-ICP](kiss-icp.md) and
  [LIO-SAM](lio-sam.md) are the livelier options.

## Setup

Jazzy has `cartographer` 2.0.9004 and `cartographer_ros` 2.0.9003 [8]: the forks number releases
`(upstream patch + 900) × 10` on a 2.0 base, for upstream cartographer 2.0.0 [3][4]. Linux only;
no GPU code [4].
`cartographer_node` reads a Lua config (`-configuration_directory`, `-configuration_basename`)
whose `options` pick the inputs (`scan`, `echoes`, `points2`, `imu`, `odom`, `fix`) and frames;
`cartographer_occupancy_grid_node` publishes `/map` for Nav2 [3][5]. Install, then save a map:

```bash
sudo apt install ros-jazzy-cartographer-ros ros-jazzy-cartographer-rviz
ros2 service call /finish_trajectory cartographer_ros_msgs/srv/FinishTrajectory \
  "{trajectory_id: 0}"
ros2 service call /write_state cartographer_ros_msgs/srv/WriteState \
  "{filename: '/home/robot/office.pbstream', include_unfinished_submaps: true}"
```

`cartographer_pbstream_to_ros_map -pbstream_filename <file>` writes ROS map files. Localize with
`-load_state_filename` and `TRAJECTORY_BUILDER.pure_localization_trimmer`, as in
`backpack_2d_localization.lua` [3]; `POSE_GRAPH.optimize_every_n_nodes = 0` isolates local SLAM [6].

## Traps

- **2D mapping waits for an IMU.** `TRAJECTORY_BUILDER_2D.use_imu_data` defaults to true [4];
  set it false on a robot without one. In 3D an IMU is required [6].
- **Two parents for `base_link`.** If wheel odometry publishes `odom → base_link`, set
  `published_frame = "odom"` so it adds only `map → odom`; keep `provide_odom_frame` off [5].
- **Example launch files mislead.** The grid node reads `-resolution` as a command-line flag, but
  they pass a ROS parameter (fork issue 86), and `backpack_2d.launch.py` forces `use_sim_time` true
  on it [3]. Pass `-resolution` in `arguments` and set sim time yourself.
- **Old docs, no answers.** The docs show ROS 1 commands (`rosservice`, `roslaunch`) [7]; upstream
  answers no issues [1], and the fork's newest issues have few or no replies [3].
